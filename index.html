FDA Adverse Event Signal Analysis

In progress

Disproportionality analysis of FDA's FAERS database, computing reporting odds ratios with confidence intervals across 150,421 drug-reaction pairs drawn from 385,288 deduplicated case reports, with a Benjamini-Hochberg correction for multiple testing.

ρ = 0.76 Correlation between signal strength and how concentrated an event's reporting is in one drug
98 / 100 Top-ranked signals traceable to a single drug dominating reports of that event

The finding. On a single quarter of FAERS, the strongest statistical signals reflect reporting patterns more than pharmacology. Litigation-linked reporting clusters and high-polypharmacy submissions each produce them, and together they account for 65% of all nominal signals.

Method. Deduplicated by case ID keeping the latest version, identified drugs by active ingredient rather than free-text name, and restricted to primary and secondary suspect drugs. Every 2×2 contingency table is verified to sum to the population count at runtime.

Validation. Before artifact filtering, top candidates included pharmacologically absurd pairs like a topical steroid with congenital hiatus hernia. After filtering, the same positions are held by documented adverse effects: testosterone with polycythaemia, daptomycin with eosinophilic pneumonia, CAR-T therapy with immune effector cell-associated neurotoxicity.

Flight Price Predictor

Live

A daily collector pulls flight prices from the Google Flights API into SQLite and trains a classifier to predict whether a given flight's price will rise before departure. The full pipeline, from collection through training, evaluation, and dashboard deployment, runs unattended on GitHub Actions.

Evaluation. Chronological train/test split so the model is scored only on data it hasn't seen. A random split would leak future prices into training. Every accuracy figure is reported against a majority-class baseline, since accuracy without that comparison isn't interpretable.

Data integrity. Records are tagged by source, so live API prices stay separate from the simulated fallback the collector uses when the API times out. The model trains on real prices only.

Automation. GitHub Actions runs the pipeline nightly, commits the updated database, and redeploys the dashboard to GitHub Pages.
